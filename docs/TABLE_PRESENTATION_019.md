# 0.1.9：百家樂一體賭枱、大小分區

使用者已明確選定：「百家樂採用一體賭枱版，大小採用分開兩區版」。此指示滿足前次「先預覽，確認後才實裝」的要求，現在接入已展示的版式；預覽歷史在previews/baccarat-proportions-v1。

## 玩家可見的結果

- 百家樂把開牌、投注、籌碼與操作置於同一張連續翠綠枱布，只有外圍酒紅／金色枱框。內部用金線上下分隔，不再把開牌區畫成另一張小枱。
- 頂部資訊及導航以外，上方開牌約35%、下方投注及操作約65%。莊／閒各自成組置中，卡牌隨上區可用尺寸放大。直屏空間足夠時莊／閒在上區分兩行，短橫向用行內標示保留卡牌空間。
- 六個投注格依實際盤面長寬重新排成三列兩行，完整使用下區可用寬高，不以固定1200×610比例縮在中央。文字及籌碼各自依幾何配置，沒有把PNG或字體橫向拉扁。
- 無投注時標籤居中；下注後文字稍移左，籌碼與金額放在該格右側，避免覆蓋賠率。飛入與落枱使用同一份幾何，縮放時不改投注值。
- 大小保留分開的上方骰盅區與下方完整投注枱，明確標記presentation-separated；50格幾何、倍率、精準選格、主動放大及原控制不改，沒有把百家樂一體樣式套到大小。未強迫大小用百家樂的六格排列或35／65比例。
- 底部主要操作、次要dialog、暫停遮桌、慢速發牌及咪牌仍保留；手圖仍刪除。所有資金、賠率、牌序、道具及保存schema1保持。

## 實作及檢查

src/baccarat-view.mjs新增baccarat-felt與baccarat-lower結構；styles.css用35fr／65fr網格及透明內區共用一次枱布。src/table-layout.mjs測量實際開牌及盤面尺寸，設定卡牌尺寸與版式，並用相同長寬比重建投注SVG。src/board.mjs的baccaratCellsForHeight同時供印刷格、已押籌碼及ChipFlights使用；app在render、window／visualViewport resize後重排並重畫籌碼。只有尺寸改變才重建SVG，避免下注點選時重複繪製。

102項檢查通過（原94＋8版式），新增包括寬窄／高矮六格邊界及不重疊、落枱金額／飛行對應幾何、卡牌尺寸、重排readonly保留、實際視圖上下共用一張枱、大小分區及50格、鎖注／牌靴／道具不受重排影響。原4,000局資金與道具模擬保持通過；十張PNG位元組不改，無新素材下載。

docs/previews/table-presentation-019/board-empty.png及board-selected.png檢查正式SVG的寬盤面／下注標籤和籌碼；由Inkscape呈現。選中圖以等效SVG transform代替CSS變數供Inkscape檢查，不是瀏覽器CSS驗收或遊戲截圖。

browser_smoke.py已加入真實幾何的35／65上下關係及SVG／可用盤面長寬比檢查，Python語法通過，但尚未實跑。既有Chromium IPC限制繼續有效，不重試相同失敗路線。

## UI狀態與限制

P1：尚缺Safari實測來證實縮放、直屏／短橫向、第三張與換牌按鈕大小、原生dialog、方向切換及字體放大。上35／下65屬已採用預覽的基準，極矮視窗仍可能讓總覽細小，不能由程式測試推定所有螢幕可讀性通過。保留大小的精準選格／放大及百家樂明細。

UI Score：Readable／UX／Accessibility／Commercial／Retention／Google Play Risk皆未評分，無新的實機證據。Priority：P0主操作可達性需實機確認；P1上下比例／SVG與籌碼對位；P2觸控與旋轉；P3連續枱布與金線；P4維持已確認動畫。

720×1280、1080×2400、390×844、320×568、844×390、768×1024、1024×768、Safari及實體六吋裝置仍UNVERIFIED。遊戲只支援繁體中文；留存及商店評分未測量。
