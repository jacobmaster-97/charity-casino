五桌完成派彩後統一開居中的小視窗，顯示本局損益、投注、退回及派彩，以及適用的佣金／保本。保留再玩一局／一手、返回大廳、自由模式手動保存及查看盤面；盤面只保留「查看派彩」入口。金額直接用原result與money／cashAbs讀取，不重新計算或發放。

結果小視窗使用原modal鍵盤Tab圈與inert阻擋背景操作，但背景牌桌仍可見。橫向矮畫面用雙欄壓縮空間，內部必要時可捲動；不加整頁高度。操作至少44px。使用真正viewport高度及safe-area，未硬寫手機裝置數字。

## 貼圖處理

根因假設：原先只有進桌後新DOM／CSS才請求及解碼相關大型PNG；反覆innerHTML換場亦可能觸發重新解碼。每張約0.9–2.1MB，冷快取時會晚於介面出現。這是原始素材及載入生命週期證據，並非實測Safari網路瀑布圖。

TableArtCache放在既有table-layout.mjs，由app建立一次並保留Image參照。首頁閒時開始按順序預載九張共用牌桌PNG，避免背景同時解碼全部圖片；按桌入座時優先準備該桌所需清單。相同URL共用同一Promise與已解碼圖片，CSS、SVG及離線data URL均沿原art resolver，不新增網路服務或素材副本。

只有該桌所需圖片都load及decode完成才呼叫原Game.enterTable。未備妥時先顯示準備小視窗，挑戰倒數繼續；可暫停或返回大廳。每張15秒逾時或載入／解碼失敗後提供重試，保留已完成圖片，只重試缺失項。取消／換請求後舊完成回呼不入桌；背景暫停時完成解碼也會等按繼續；五分鐘到則清除待入桌請求並顯示挑戰結果，不開新局。

這項改善把下載與解碼提早並重用，不減少PNG位元組、不保證某個秒數。冷快取／慢網路仍可能等待，準備視窗用於避免半張盤面。九張解碼圖片的記憶體成本及Safari是否仍自行逐出材質，需要裝置量測；目前沒有取得前後載入耗時，不宣稱速度百分比。
